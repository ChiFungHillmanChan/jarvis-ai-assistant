## 審查結論

已沿首次啟動、語言偏好、郵件同步與 MIME 抽取、原信／分析／文件呈現、本機儲存、工作區快取及公開安裝檔逐條檢查。原有自動測試通過，仍找到測試未涵蓋的實際問題，因此「測試通過」不等於所有功能沒有錯誤。

本輪修改保留正式 Gmail 授權、API 密鑰、既有供應商、原始郵件及已安裝 App。測試使用合成郵件、隔離 SQLite 和記憶體憑證；沒有向真實 Gmail 寄信或刪除原信，沒有下載本機 AI 模型。

## 已修正的問題

| 重要程度 | 原有問題及影響 | 本輪修正 |
| --- | --- | --- |
| 高 | 首次啟動直接進入模型設定，沒有清楚詢問語言及提供相應說明 | 新增必須選擇的語言對話框，以及中英文入門說明。選擇寫入本機後才繼續 |
| 高 | 語言設定非同步寫入；快速切換或完成導引可能保存舊選擇 | 按次序寫入偏好，等待儲存完成；失敗顯示重試，不冒稱成功 |
| 高 | 啟動偏好讀取失敗時直接當作已完成設定；後端亦吞掉資料庫讀取錯誤 | 顯示可重試錯誤，資料庫問題向上傳回 |
| 高 | 新安裝沒有 `ui_locale` 或入門偏好時，舊介面把「未設定」當作錯誤，首次啟動被阻擋 | 對可選偏好使用設定集合讀取，保留真正讀取錯誤；已用全新原生 QA 資料庫驗證 |
| 高 | 郵件分析使用 `<pre>`，表格、粗體及標題直接顯示 Markdown 符號 | 共用排版元件處理標題、清單、表格、引用及程式碼；有效郵件引用可點擊 |

| 高 | MIME 搜尋可能把文字附件或附上的郵件當作正文；非文字內容亦可能顯示為正文 | 依檔名、Content-Disposition 及 MIME 類型排除附件，保留真正正文 |
| 中 | HTML 中 style 先於 script 時混入 CSS；數字字元實體未解碼，巢狀實體被重複解碼 | 按文件次序移除 script/style，字元實體只解碼一次，支援十進位及十六進位 Unicode |
| 高 | 儲存設定缺失或損壞時仍套用 90 天清理 | 無法確認有效設定時停止自動清理；正常新安裝仍沿用 migration 設定的 90 天 |
| 高 | QA 儲存頁面指向正式資料夾；清理根目錄為符號連結時可能碰到目錄外檔案 | 使用實際開啟的資料庫目錄，隔離 QA 快取，拒絕清理符號連結根目錄 |
| 中 | 中文正文用字元數當作 bytes；清理後 VACUUM 重新膨脹 WAL | 按 UTF-8 bytes 統計，VACUUM 後再截斷 WAL |
| 中 | 工作區只保留 20 個最近關閉的分頁，但其餘文件結果仍永久累積 | 儲存及還原時清除已無法從分頁或最近紀錄開啟的結果快取，保留可返回的草稿及結果 |
| 中 | 儲存頁聲稱所有資料不會上傳，亦籠統稱所有項目都可安全移除 | 中英文說明區分本機副本、雲端分析、統計範圍及備份刪除不可復原 |

原信採可換行的文字呈現，保留寄件人的內容，不把原信中的星號、底線或方括號誤當 AI 指令或圖表。AI 生成的摘要使用正常排版；這兩者不會互相覆寫。外部圖片不會自動載入，HTML 腳本不會執行，連結限制在可接受的網址協定。

## 本機儲存及輕量程度

正式 SQLite 路徑為 `~/Library/Application Support/jarvis/jarvis.db`。Gmail 權杖和 API 密鑰使用 macOS 鑰匙圈。SQLite 本身沒有應用層加密；使用 GPT 時，分析需要的郵件、指示及記憶仍會傳送至 OpenAI。本機保存副本不代表離線推論。

本輪只讀取檔案大小，沒有讀取私人郵件內容或清理正式資料。現有 Mac 的量度如下；這是已使用一段時間的安裝，並非新用戶的固定需求：

| 項目 | 實際大小 |
| --- | ---: |
| 已安裝 JARVIS.app | 32,562,222 bytes，約 31.1 MiB |
| SQLite 主檔 | 798,720 bytes，約 0.76 MiB |
| WAL 及 SHM | 4,161,040 bytes，約 3.97 MiB |
| 既有備份 | 191,140,960 bytes，約 182.3 MiB |
| `Caches/jarvis` | 97,445,973 bytes，約 92.9 MiB |
| `Caches/com.jarvis.app` 及 WebKit 資料 | 1,637,810 bytes，約 1.56 MiB |
| 上述已知 App／資料／快取合計 | 約 312.8 MiB |

本機模型目錄沒有佔用資料。使用 GPT 電郵流程不需要下載 Ollama 模型；開啟本機語音或本機 AI 才會有額外模型空間需求。開發用 `node_modules`、Rust `target` 與 QA debug bundle 不屬於用戶 DMG 的安裝大小。

現有儲存頁面的總計不包含 App 本身、所有 WebKit 目錄或外部 Ollama 模型，不應把頁面數字稱為整部 Mac 的完整佔用。保留期限針對部分正文及歷史內容；已分組郵件、郵件資料列、群組與記憶會保留。清理在啟動及手動操作時執行，沒有固定的全域磁碟容量上限。

因此，現有郵件文字儲存的體積較小，但仍不能保證多年使用後不會增長。備份及快取是這部 Mac 目前的主要佔用，本輪沒有刪除。大量資料時，完整 SQLite `VACUUM` 亦可能延長啟動清理時間；未做大型信箱效能壓力測試。

## 文件和附件的實際支援

現有同步保存可讀郵件文字，沒有 JARVIS 內的 PDF／Word／Excel 附件下載或預覽引擎，亦沒有把郵件自動匯出成 DOCX／PDF 的流程。本輪不把這些功能描述成已完成。

新增「在 Gmail 查看原信及附件」入口，按郵件所屬帳戶開啟 Gmail，讓使用者在 Gmail 下載原檔。原本 HTML 郵件的複雜版面、內嵌圖片及附件，仍應以 Gmail 和原始文件應用程式顯示為準。已保存的舊郵件需重新同步，才會套用本輪正文抽取修正。

## 用戶下載及開始使用

1. 公開版本目前是 [JARVIS v0.4.1 安裝檔](https://jarvis-releases.s3.ap-east-1.amazonaws.com/JARVIS_0.4.1_aarch64.dmg)，適用於 Apple Silicon Mac；設定最低 macOS 12。此安裝檔尚未包含本輪修正。
2. 開啟 DMG，把 JARVIS 拖到「應用程式」，再從「應用程式」啟動。一般使用者無須安裝 Node、Rust 或編輯 `.env`。
3. 本輪修正版發布後，新用戶首次啟動先選擇 English 或繁體中文（香港），閱讀相應使用說明，再選擇「設定電郵」。已完成設定的舊用戶不會被迫重跑；介面語言可在「設定 → 外觀」修改。
4. 在電郵設定導引選擇 OpenAI，儲存自己的 API 密鑰並測試。電郵模型與 AI 助理、語音設定各自獨立；保留已能使用的模型，測試成功後才套用。服務帳戶資格、API 餘額及網絡仍會影響可用性。
5. 按「連接 Gmail 帳戶」，在 Google 瀏覽器授權頁選擇需要的帳戶，再同步首批郵件。每次最多 50 封；按「載入更舊郵件」繼續。若 Google 顯示帳戶未獲允許，發行者需處理 OAuth 狀態，使用者不應反覆重裝。
6. 建立群組，選取郵件加入，填寫整理指示；例如：「列出要回覆的問題、截止日期及文件要求，所有結論附原信來源」。按「分析此群組」，再點擊來源核對日期、金額及文件要求。
7. 如需附件，按「在 Gmail 查看原信及附件」，在 Gmail 下載原檔。切勿把 AI 摘要當成原附件。
8. 在「設定 → 儲存空間」查看資料佔用及保留期限。已分組郵件會保留；刪除備份是不可復原操作，不應只為追求數字較小而移除唯一可還原的副本。
